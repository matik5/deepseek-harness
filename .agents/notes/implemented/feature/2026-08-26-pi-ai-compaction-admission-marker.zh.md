# Agent Note：pi-ai 压缩准入标记

状态：implemented

[English](2026-08-26-pi-ai-compaction-admission-marker.md) | 中文

## 问题

[压缩能力决策](2026-06-18-compaction-capability-seam.zh.md)使 Compact-basic 用 `GenerateOptions.purpose = 'compaction'` 标识摘要器调用，但 pi-ai 适配器丢弃了这个仅用于传输的 purpose。因而，保护恢复预留空间的网关会对摘要器本身套用普通请求的严格输入上限。接近上限时，原请求虽能正确触发溢出恢复，恢复请求却可能超过同一上限，使会话陷入无法压缩的状态。

## 决策

Pi-ai 适配器只在 `purpose === 'compaction'` 时把它映射为提供方请求标头 `x-deepseek-harness-compact: 1`，与直接 DeepSeek 适配器已有的 wire 契约一致。该标记不会进入模型可见的请求体。它与归因标头一样归 Harness 所有：配置的 profile 标头会按大小写无关方式过滤，因此部署无法把普通请求永久标为压缩请求，也无法替换标记值。

网关可以用这个精确标记选择恢复专用准入上限。网关仍须执行物理上下文边界并预留输出空间；该标记描述请求用途，并不授予超出模型窗口的权限。

## 备选方案

**提高公布的模型上下文或普通网关输入上限。** 否决，因为这会让每个 agent 回合都进入恢复预留区，重新制造该预留本应避免的缓慢、难以压缩状态。

**从摘要提示词、请求大小或 User-Agent 推断。** 否决，因为提示词检查脆弱且涉及模型可见内容，而请求大小与归因都无法区分用户回合和内部摘要器调用。

**允许配置的 profile 标头提供该标记。** 否决，因为 profile 标头应用于路由上的每个请求，会静默取消普通准入边界。

## 后果

Pi-ai 路由现在可以与为恢复专门预留上下文的网关协作，使溢出触发的摘要有空间运行，而普通请求仍停留在运行上限之下。非压缩请求除移除冲突的配置标记外保持不变。忽略该标头的网关继续保持原有行为。
